## Fresh retained-candidate capacity probes

The earlier `pro6000-capacity-v1/report.json` belongs to weights-only executable `1f980362`; it is preserved as historical evidence. A new `acceptance-capacity-v1/` campaign builds the current checked CLI on the workstation, pins the retained source and final cold configuration, and runs these probes serially in both builds. All tuning flags and graphs are enabled; correctness probes additionally enable full-logit verification.

| Probe | Configuration and required result | Retained release | Fresh checked |
|---|---|---|---|
| Native output overflow | 32,768 prompt tokens plus one requested output; 64 GiB KV. Require exit 1, empty stdout and exactly `Error: request exceeds context or is empty`. | Pass | Pass |
| Single-request pool exhaustion | Sixty-five prompt tokens plus one output; one 64-token page, 9,437,184 bytes. Require exit 1, empty stdout and exactly `Error: KV cache capacity exhausted`. | Pass | Pass |
| Single-page exact fit | Sixty-three prompt tokens plus one output in one page. Require one complete generation, sixty-three processed tokens, zero reused tokens and matching release/checked token and full-logit hash. | Pass | Pass |

Both successful records report zero used pages and references after the call. These are acceptance probes, not latency samples. The final flags are present, but a one-output request does not dispatch the head path that requires exactly thirty-two outputs. The prior native and full-model head tests supply that distinct coverage.

The checked CLI SHA-256 is `0bf26c73db5445ad8c7f17582358086427283fb8aa2acff694bd4fa5278db87e`; the six-probe completion is `2715f5da58fca153d4854b379105f02dc39473b49990565dd0e90617fa6acaf5`.
