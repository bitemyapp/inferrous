# Known numerical differences

## DISC-001: Full-model floating-point/quantization sensitivity

Status: INVESTIGATING; reviewed 2026-10-21. Affects `smoke-request.json`, every full-model comparison; the failing report is summarized in the [2026-10-02 results](results/rounds-1-2.md). The historical onset audit below narrows the diagnosis; a fresh GPU comparison is queued on `wx-workstation` and has not passed.

The independent Torch composition and cuda-oxide generate the same three tokens (`12095, 13, 576`). They fail the predeclared full-tensor numerical gate. Logit relative L2 is about 9–11%, despite identical first-token argmax. Individual operator fixtures pass substantially tighter thresholds.

Tracing the first divergence found identical layer outputs through layer 3. A CPU replay of the stored layer-4 traces on `wx-workstation` now locates the first difference in K normalization: the pre-normalization Q/K arrays and post-normalization Q arrays agree exactly, while post-normalization K differs only at token position 0, KV head 5, coordinate 123. The stored Torch value is `6.40625`; both stored Rust variants produce `6.4375`. RoPE is the identity at position 0, so this particular onset precedes any nontrivial rotation.

Using the same pinned input and normalization gain, a 100-digit Decimal evaluation gives `6.421875251728874…`, just `2.5172887e-7` above the BF16 midpoint `6.421875`. Rounding that high-precision result directly to BF16 gives the Rust value. An independent FP64 normalization replay with the pinned RoPE table matches every stored Q/K post-normalization value from Rust. This diagnoses a sensitive rounding boundary; it does not establish which implementation's FP32 operation sequence is required, validate the rest of the model, or replace the original reference.

A further CPU FP32 sensitivity replay evaluates the Rust strided reduction, two adjacent-quad reductions, an adjacent pairwise tree, sequential accumulation and the rounded exact sum. Their sums occupy two adjacent FP32 values, but the correctly rounded reciprocal square root of each resulting FP32 statistic has bits `0x4128b66a`. The declared FP32 multiplies then land exactly on the BF16 midpoint and round to `6.4375`. Using an inverse one FP32 ULP lower (`0x4128b669`) instead produces `6.421874523162842`, which rounds to the historical Torch value `6.40625`. This isolates a sufficient rounding sensitivity; it does not attribute any simulated reduction or inverse to Torch's actual CUDA kernel. Fresh GPU intermediates remain necessary for that attribution. `historical-norm-order-sensitivity-v1.json` has SHA-256 `3e6a8dd337211b421291f0287722c639676e529256f29845485713d67b59f26d` and preserves every intermediate bit pattern and source identity. Neither the full-model gate nor a production arithmetic path changes.

The subsequent trace contains small attention differences and larger MLP differences after dynamic INT8 quantization. Ordinary FP32 reductions, reciprocal square root, exponential approximations and BF16 rounding need not agree across implementations; repeated quantization can amplify those differences. The observed onset is not proof that all discrepancies are harmless. Do not claim model quality or cross-engine numerical equivalence from the performance measurements.

Both the historical traces and the workstation's 4K bundle use root `e51d2517784b99de3802110542e831061489bf00df33db1b412ba3b3d01d21d7`. All 651 non-RoPE tensor descriptors match the separate native-context bundle, whose first 4K RoPE bytes also match. This descriptor/prefix audit does not replace the loader's full tensor integrity checks. Evidence under `clean-work/pro6000-baseline/` is `historical-qk-audit-v2.json` (SHA-256 `2a21ce8176af6e40bda6aefba35c752bea9b835b3fb20c3d0d0b0594f5b9d155`), `historical-norm-boundary-v1.json` (`2eccbf19814a2f7e97bb91cf3691e972983ecf2ca8f9fda528703612a934d6a3`) and `historical-native-input-identity-v1.json` (`8b2e2278c5547870607409edd20080300c67408d3780093448b3effcfd498c37`). The preserved v1 audit's scope prose incorrectly said the roots differed; v2 corrects that prose without changing the numerical observations.

The queued fresh comparison runs the unchanged Torch reference first, then separately labeled diagnostics using the bundle's RoPE table and an FP64 RMS statistic/inverse rounded to FP32 before the original multiplies. All variants use the unchanged full-tensor comparator. A diagnostic pass cannot substitute for an original-reference failure. See [round 8](optimization/round-8.md#fresh-numerical-reference-comparison) for identities and execution status.

Optimization regression checks compare *all* vocabulary logit hashes and token IDs against the original cuda-oxide baseline, in addition to independent operator fixtures. They do not replace this separate, still-failing oracle gate.

## DISC-002: Fused floating-point operator boundaries

Status: ACCEPTED as an explicit baseline convention; reviewed 2026-10-02. Affects comparisons against eager Hugging Face Qwen3, distinct from DISC-001.

Norm multiplies the gain before the final BF16 cast; RoPE uses FP32 coefficients and one output cast; softmax probabilities remain FP32 until PV is cast; SiLU and the up projection multiply before the final BF16 cast. These are ordinary fused inference semantics. Eager frameworks can materialize additional BF16 intermediates. The independent composition documents these same boundaries. Bitwise equality to arbitrary eager/serving frameworks is not a requirement.
