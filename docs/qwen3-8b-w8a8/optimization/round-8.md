## Profiling and implementation

The baseline batch-32 CUPTI trace contains 31,224 records, and the solo 8K trace contains 41,829 records. Both have complete footers with zero dropped or invalid records. Batch-32 eager time is 60.5% `linear_large`; its graph time is 57.7% `head_packed_rows` and 35.3% `linear_tiled`. Solo 8K eager time is 44.7% paged PV and 42.0% paged QK. Instrumented timings are diagnostics, not performance measurements. Artifacts are `b32-p129-*v2.*` and `b01-p8192-*v2.*`.

The CUPTI wrapper now supports the toolkit's `lib64` layout and its current activity record type. CUDA 13.1 declares `CUpti_ActivityKernel11`, while the original code assumed CUDA 13.4's `CUpti_ActivityKernel13`. Header/runtime API versions must agree. The first profiling attempt failed at compile time and is not counted as a trace.

The handoff's QK/PV sketches are integrated as opt-in tiled prefill kernels. Host-built groups contain at most four contiguous rows from one session; groups never cross a slot or position discontinuity. `Step` owns the captured metadata. At least two rows per group on average are required; decode keeps existing kernels. Partial groups and causal tails preserve each row's FP32 term order and BF16 rounding. See the [safety argument](../safety.md#tiled-paged-prefill-attention).

Explicit tuning flags now work on either validated hardware profile, allowing the existing projection pipelines and grouped/staged heads to be evaluated on the PRO 6000. The PRO defaults remain disabled pending the acceptance work. `tiled_attention` defaults to false on both profiles. The legacy engine's policy remains unchanged.

The operator profile compares original, grouped and tiled attention. For 256 rows, the measured median combined QK/softmax/PV time at strides 512/4096/32768 is respectively 0.340/3.355/33.905 ms for original kernels, 0.145/1.460/16.649 ms for grouped kernels, and 0.112/1.120/13.626 ms for tiled kernels. These isolated diagnostic samples do not establish model-level improvements. All operator outputs agree exactly. Artifact: `tiled-operator-profile.log`.

## Isolated fused-attention experiment

Static inspection of the embedded CUDA image in `weights-only-candidate-v1` shows 42 registers, 25,600 bytes of shared memory and no stack/local storage for both tiled QK variants. Both have 6,144 bytes of code and 384 disassembled instructions; only four loop-control instructions differ. The compiler already processes eight ordered channel terms per loop in the original kernel, so the explicit unroll hint does not expose additional terms. The direct BF16 sixteen-output head uses 48 registers versus 56 for its packed counterpart; the eight-output versions both use 40. Their shared-memory allocations are unchanged. These are compiler diagnostics, not measured performance gains. Complete extracted-image identities, resource reports and QK assembly differences are under `resources-v2/`; the first extraction omitted the ELF program-header table and is not valid inspection evidence.

A separate worktree at `/home/callen/work/inferrous-fused-attention`, based on `ac4a3cb` plus the recorded pending source patch, contains an operator-only fused attention prototype. It trades three QK evaluations for eliminating the global score/probability matrix round trip: the first pass finds the maximum, the second computes the denominator, and the third normalizes each 64-key stripe and immediately accumulates PV. It retains ascending QK channel order, the original per-lane softmax key sequence and 128-lane reduction tree, ascending PV key order, separate FP32 operations and the final BF16 cast. Partial groups duplicate only read-only staging and never publish padded rows. The 512-thread block reuses its 16 KiB K/V tile as reduction scratch after all consumers finish; the total reported shared allocation is 29,696 bytes. Exact output equality is the acceptance contract; no oracle or arithmetic tolerance has been replaced.

The initial looped form compiles with 68 registers and no stack storage. Specializing its three phases produces 72 registers without a launch bound. A second variant requests `launch_bounds(512, 2)` and compiles with 64 registers plus an 8-byte stack frame; ptxas explicitly reports 8 bytes of spill loads and stores. Both bounded and unbounded variants remain in the operator profile so timing can evaluate the occupancy/spill tradeoff. No production dispatch or main-worktree source changed. Rechecking the main candidate's source diff yields the original SHA-256 `28eb601fd73bd0d08abd103aee2c116455d6fe32ef8d1c3ce6122d8ff3842e5a`.

## Online tensor-core attention: separate numerical experiment

The plan permits new attention arithmetic with independent references and an explicit numerical contract. The isolated `/home/callen/work/inferrous-online-attention` worktree, based on `5ab7e01`, explores that option without changing production dispatch, the declared legacy path or its hashes. Unlike the rejected three-pass exact fusion, this candidate uses BF16 QK tensor-core products, FP32 online softmax and FP32-accumulating PV tensor-core products. Each FP32 probability is expanded into three BF16 residual components for PV; it is not simply rounded once to BF16. Eight contiguous queries share each 64-key stripe, and softmax/output state advances in a fixed key-page order. Q inputs must already be BF16-representable, as they are at the model's declared Q/K preparation boundary. This kernel is not interchangeable with the arbitrary-FP32-Q exact operator.

This is a different accumulation contract. ## Head interval feasibility and further completed partitions

The saved batch-32 candidate CUPTI profile assigns 37.2% of graph kernel time to the sixteen-row output head, with median instrumented duration 5.145 ms. A CPU feasibility screen on `wx-workstation` investigates accepting a faster approximate dot only when an error interval rounds to the same BF16 value throughout, then recomputing ambiguous outputs with the unchanged ordered head. This preserves the intended full-vocabulary contract rather than merely validating argmax. NVIDIA's [PTX MMA documentation](https://docs.nvidia.com/cuda/parallel-thread-execution/#warp-level-matrix-instructions-mma) leaves BF16 accumulation order, rounding and subnormal handling unspecified, so this screen does not assume a particular BF16 tensor-core error model.

The proposed center instead uses power-of-two INT16 approximations `a` and `b` of the original BF16 input `x` and weight row `w`. Its integer dot is exact in FP64 for these dimensions and could be decomposed into four bounded signed-INT8 dots. The representation error is bounded by `||x-a||₂ ||w||₂ + ||a||₂ ||w-b||₂`. A separate conservative `gamma_134 ||x||₂ ||w||₂` allowance covers the legacy 128-term lane accumulations and five warp-reduction stages. Norm calculations and interval endpoints include outward rounding allowances. This is a feasibility calculation over captured finite inputs within checked exponent limits, not general-domain validation of a GPU implementation.

The complete six-input screen checks every vocabulary value from the three steps of each five/513-token hidden32 control. It certifies only five of 911,616 outputs; all five match the captured Rust logits, and every captured rounded output lies within its corresponding rounded interval. Unchecked rounding of the approximate centers would change 7,580–23,112 logits per input. Thus this coarse INT16 design would almost always execute the full fallback and does not merit a GPU implementation. The initial signed-byte decomposition used nearest-even high-byte rounding and failed its low-byte range assertion; that failed attempt remains preserved. The corrected decomposition uses `floor((q+128)/256)` and verifies exact reconstruction and signed ranges.

A second screen removes integer quantization error entirely, using FP64 BF16-input dots with a separate FP64 reduction allowance. It estimates the best-case feasibility of this particular legacy-rounding bound; it is not a measured fast implementation.
